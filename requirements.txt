# Dependencies for app.py, the Streamlit prototype.
#
# Deliberately separate from backend/requirements.txt. This app only ever runs
# inference -- it loads the committed artifact through xgb.Booster and never
# fits -- so it needs neither scikit-learn nor scipy, which together are ~145 MB
# of the backend's dependency tree.
#
# Used by Streamlit Community Cloud, which installs this file at deploy time.
# Locally, `pip install -r requirements.txt` then `streamlit run app.py`.
#
# Versions match backend/requirements.txt where they overlap. numpy<2 is not a
# preference: xgboost 2.0.3's categorical encoder still calls np.NaN, which
# NumPy removed in 2.0. xgboost is pinned for the same reason as the backend --
# it is the version the committed model artifact was built and verified against.
#
# DEPLOY ON PYTHON 3.12, and treat any other version as a bug rather than a
# preference. Streamlit Community Cloud cannot change the Python version after
# deployment, so correcting it means deleting the app and redeploying with 3.12
# chosen in Advanced settings.
#
# What happens elsewhere, measured on a real 3.14 deploy:
#
#   Python 3.14 has no numpy 1.x wheel, so pip/uv builds numpy from source.
#   That takes about three minutes and it does succeed, so the deploy looks
#   like it is hanging rather than like a version problem. numpy 1.26 predates
#   3.14 by two releases, so a source build of it is also outside numpy's own
#   support window.
#
# Do NOT try to fix this by pinning numpy with an environment marker such as
# `; python_version < "3.13"`. That was tried and it is worse than useless:
# excluding the direct numpy pin does not exclude the transitive requirement,
# so pandas, streamlit and scipy simply resolve numpy 2 instead, and
# xgboost 2.0.3 then fails at load time because its categorical encoder calls
# the np.NaN that numpy 2 removed. The pin has to be unconditional so that
# resolution fails loudly here rather than silently installing a numpy that
# cannot work.
#
# Moving to 3.13+ properly means numpy 2.x, which means dropping xgboost 2.0.3
# for a numpy-2-compatible release, which breaks the byte-reproducibility the
# committed artifacts and tests/test_financial_impact.py depend on. render.yaml
# pins PYTHON_VERSION 3.12.4 for exactly this reason.

# Streamlit is pinned exactly, not floored. Community Cloud will otherwise
# silently upgrade it on its own schedule, which can change widget behaviour or
# a layout between deploys -- the wrong time to discover it mid-refactor. Bump
# this deliberately, alongside a local run of `streamlit run app.py`.
streamlit==1.64.0
pandas>=2.2,<3
numpy>=1.26,<2
xgboost==2.0.3
